01why a framework

Agents write code fast. Three other things break.

memory

Decisions vanish in chat

Two weeks later nobody knows why the money is an integer. The chat is gone; the code only shows what.

→ every decision is a row in the docs, with the rejected alternatives
scope

The agent builds its guess

An open question at prompt time becomes a silent assumption in the diff. Reviews then argue about the assumption, not the code.

→ the issue is the whole contract; the thinking ends before building starts
trust

Who reviewed that?

Green CI is not a review. A PR needs evidence a person can read: suites, mutations, deviations, a verdict.

→ reviewer agents with a verdict line; a fix loop; a trail per issue
02the shape

Three sessions, one repo. GitHub is the only shared state.

1 · rumble

Think and decide

A person and the model, with web search. Reads the brief, asks back, researches, writes decisions, gaps, measurements, a roadmap.

/task-out
ends with issues on GitHub — never builds
2 · pipeline

Orchestrate

A fresh session. Never reads code. Briefs agents, reads verdicts, merges, posts the trail — in waves of at most three builders.

/pipeline <umbrella>
retires when the umbrella is done
3 · agents

One job each

Triage · architect · implementer · quality reviewer · security reviewer. Each in its own git worktree, each ends with a PR or a VERDICT: line.

11several people
The issue is the contract, so the author does not matter.

  

    
rumble
Everyone rumbles. Rows and issues come as a PR and are reviewed like code. Reserved numbers avoid collisions.

    
orchestrate
One person per arc runs the pipeline. State is on GitHub, so the next wave can be taken over in a new session by someone else.

    
review
Verdicts, evidence and trails are written for a person who was not there. Disagree in a review comment — the fix loop treats it like a finding.

    
merge
gate.merge: human and the gate stops at “ready for review”. CODEOWNERS per area decide who the inbox is.

  







  
12where this fits
Agent features are decisions plus contracts plus reviewed PRs.

  

    
buyer · merchant agents
What an agent may do is a D-row and a risk label before it is code. Requisit's drafting agent never approves — decided in the rumble, enforced in review.

    
pwa · commerce core
One framework repo, one framework.json per codebase: its own areas, implementers, verify board and risk:high list.

    
both runtimes
Claude Code and Codex from the same source; the model per stage is a binding, not a habit.
